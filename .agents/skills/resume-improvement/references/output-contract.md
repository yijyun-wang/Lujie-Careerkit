# 輸出約定

## 只診斷

按以下順序輸出：

1. **診斷概覽**：候選人當前定位、主要證據和最大風險，控制在一段。
2. **已有優勢**：3—6 條，每條對應真實材料。
3. **問題分組**：優先處理、建議優化、可選改進；每組可按類別摺疊或使用三級標題。
4. **職缺證據矩陣**：僅職缺客製模式輸出。
5. **職缺研究依據**：僅使用了聯網資料時輸出，結論旁附連結。
6. **推薦處理範圍**：列出預設建議勾選項和需要補充的事實。

不要在只診斷模式輸出改寫後的完整履歷。

## 改寫交付

至少包含：

1. **優化摘要**：實際處理了什麼、沒有處理什麼。
2. **逐項差異**：

   ```text
   位置：
   原文：
   改寫：
   理由：
   依據：
   ```

3. **待確認項**：不能安全改寫的數字、職責、技能或時間。
4. **完整優化稿**：使用者要求完整稿時提供。
5. **事實複核結果**：說明是否發現新增事實、強度升級或身份欄位變化。

## 檔案處理

- 預設儲存為新檔案，如 `原檔名-優化版.md`、`原檔名-職缺客製版.docx`。
- 使用者要求直接編輯原始檔時，先保留可恢復副本或使用版本控制。
- 無法保持 PDF/DOCX 原佈局時，先交付 Markdown/純文本改寫和差異，不偽稱已經保留版式。
- 結構化輸出應使用通用欄位，不依賴某個產品內部 JSON Schema，除非使用者明確提供目標 Schema。
