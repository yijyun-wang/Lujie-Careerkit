# 傳送前品質檢查

## 事實

- [ ] 所有候選人經歷、技能、數字和結果都來自材料。
- [ ] 可到職日、實習時長、每週天數、地點和畢業時間均已確認。
- [ ] 「參與、協助、負責、主導」的強度沒有升級。
- [ ] JD 要求沒有被偷換成候選人能力。
- [ ] 公司事實有最新來源，推斷已明確標註。
- [ ] 沒有替使用者編造長期關注、文化認同或夢想加入等動機。

## 契合度

- [ ] 選擇的是與職缺最相關的 2—3 個證據，而不是最華麗的經歷。
- [ ] 技能後面有專案、任務或結果支撐。
- [ ] 公司背景只保留與職缺和候選人證據有關的內容。
- [ ] 缺口沒有被掩蓋成已掌握。

## 表達

- [ ] 前兩句已經說明關鍵價值。
- [ ] 沒有「本人性格開朗、學習能力強」等無依據模板話。
- [ ] 沒有複述完整履歷。
- [ ] 沒有關鍵字堆砌、誇張營銷話術或過度謙卑。
- [ ] 每句話都在提供契合證據、職缺理解或下一步行動。

## 管道

- [ ] 長度、禮貌程度和段落適合傳送管道。
- [ ] 公司名、職缺名、職缺編號、稱呼和附件名準確。
- [ ] 開場訊息重點在前，正式求職信有完整邏輯。
- [ ] 可直接傳送版本中沒有分析標籤、引用標記和待辦說明。

## 最後處理

發現缺失事實時，優先刪除無法支撐的句子；只有該事實會顯著改善文本時才向使用者詢問。不要在可直接傳送版本中留下 `[公司名]`、`[數字]` 等佔位符，除非使用者明確要模板。
